# فحوص HTTP المتقدمة

## الخطوات

تحتفظ الإضافة السريعة بإعداد GET الافتراضي. في إنشاء مراقب أو الإعدادات وسّع فحوص HTTP المتقدمة لإضافة قواعد وقيم طلب خاصة. يجب أن تنجح جميع القواعد المفعلة على الاستجابة نفسها؛ لا تنشئ مجموعة القواعد فحوصًا إضافية. قد تؤدي إعادة التوجيه إلى ستة طلبات كحد أقصى مع الطلب الأول.

## السلوك

القواعد: النص يحتوي/لا يحتوي، الترويسة تساوي/تحتوي، وJSON موجود/يساوي/لا يساوي/أقل/على الأكثر/أكبر/على الأقل. تبدأ مسارات JSON بـ `$` ثم مفاتيح ASCII مفصولة بنقاط أو فهارس مصفوفة رقمية، مثل `$.status` و`$.jobs[0].depth`. تُرفض المفاتيح المقتبسة والبدائل والنصوص البرمجية ومفاتيح النموذج الأولي والتعبيرات. أدخل القيم المتوقعة بصيغة `"ok"` أو `0` أو `false` أو `null` أو مصفوفة مسطحة منها. الغياب يختلف عن null وfalse والصفر والنص الفارغ والمصفوفة الفارغة. يفشل الحقل الغائب كل مقارنة حتى عدم المساواة. لا تحوّل المقارنات الرقمية النصوص إلى أرقام. يفشل JSON غير الصالح القواعد المفعلة الخاصة به.

## مثال

HTTP 200 و`$.status` يساوي `"ok"` و`$.queueDepth` أقل من `100` يتطلب الشروط الثلاثة. HTTP 200 مع `{"status":"error"}` يُعدّ متعطلًا عند تفعيل قاعدة الحالة. تعدّ الإعدادات المتقدمة حالة HTTP غير المقبولة تعطلًا. تحافظ المراقبة القديمة دون إعدادات متقدمة على سلوكها، بما فيه التدهور لاستجابة غير متوقعة أقل من 400. الزمن يقيس الطلب لا تحميل صفحة المتصفح.

## القيم الخاصة والحدود

تُشفّر الترويسات الخاصة ومصادقة Basic/Bearer ومحتوى POST معًا باستخدام ENCRYPTION_KEY الحالي، ولا يمكن استرجاعها من المحرر. الاحتفاظ يتركها كما هي؛ الاستبدال يتطلب إعادة إدخال ويحذف القيم المحذوفة؛ المسح يزيلها كلها. إغفال requestConfig في API يحتفظ بها، وnull يمسحها، والكائن يستبدلها. لا تضع بيانات دخول في الروابط أو قيم القواعد. تُرفض بيانات الدخول في رابط جديد أو معدّل. المحتوى يتطلب POST؛ تغيير الطريقة يتطلب مسح المحتوى المخزّن أو استبداله عمدًا.

أسماء الترويسات فريدة دون حساسية لحالة الأحرف. لا يمكن تجاوز Host أو Content-Length أو Connection أو Transfer-Encoding. الحدود: 20 ترويسة، 16 KiB لإعدادها المرمّز، 4096 حرفًا للقيمة، و64 KiB لمحتوى UTF-8. اسم Basic لا يحتوي نقطتين. تُستبعد قيم الطلب من صفحات الحالة والمشاركة وبيانات REST والمالك. روابط المشاركة تُغفل الإعدادات المتقدمة. تنقل القوالب والبيانات الأصلية القواعد وسياسات الزمن المدعومة غير السرية، دون قيم الطلب الخاصة.

عند استخدام قيم خاصة أو قواعد أو سياسة توجيه غير افتراضية، يعيد خيار الاتباع التحقق من كل وجهة وفق سياسة الشبكة، ويتوقف بعد خمس قفزات ويحذف الترويسات والمصادقة المهيأة عند تغير الأصل. تُرفض 307/308 إلى أصل مختلف مع محتوى. يتحول POST مع 301/302 و303 عدا HEAD إلى GET دون محتوى. الفحص يعيد أول استجابة؛ الرفض يفشل التوجيه. تتحقق فحوص HTTP القديمة أيضًا من كل وجهة إعادة توجيه. تُرفض العناوين غير المحددة وعناوين البيانات الوصفية والارتباط المحلي لأهداف HTTP(S) في جميع التثبيتات. تُسمح الوجهات الخاصة والداخلية (الاسترجاع المحلي وRFC1918 وCGNAT والعناوين المحلية الفريدة و`localhost` و`*.internal` وأسماء الخدمات أحادية المقطع) افتراضيًا مع `MONITOR_ALLOW_PRIVATE_NETWORKS=true`. اضبطه على `false` لرفض هذه الوجهات عند حفظ المراقِب أو استيراده ثم مرة أخرى عند الاتصال. تستخدم اتصالات HTTP دائمًا إجابات DNS متحقَّقًا منها وقت الاتصال.

تقرأ قواعد النص وJSON حتى 512 KiB من البيانات بعد فك الضغط. JSON بعمق 16 و10000 عقدة. قواعد الترويسات فقط لا تقرأ المحتوى. تفشل قواعد محتوى HEAD بوصفه غير مقروء دون الادعاء بملاحظة محتوى فارغ. يبقى حد المهلة خلال القراءة. الضخامة وعدم القراءة نتيجتان مختلفتان. لا يُخزّن كامل المحتوى أو القيم المستلمة للقواعد؛ يحتفظ السجل بفهرس القاعدة والنجاح ورمز سبب محدود.

## الاختبار دون حفظ

اختبار دون حفظ يجري فحصًا واحدًا صريحًا دون جدولة أو تاريخ أو تغيير الصحة. يستخدم الفاحص والإعداد الفعلي نفسيهما المستخدمين عند الحفظ. قد يؤثر POST على النظام ويتطلب تأكيدًا؛ لا يختبر الحفظ تلقائيًا. حدود الاختبار طلب متزامن واحد للحساب وثمانية لعامل الخادم؛ يستخدم التطبيق عاملًا واحدًا. هذه حدود تقنية لكل حساب.

يمكن لكل حساب استخدام مفاتيح API بنطاق `read` للقراءة و`full` للكتابة. أرسل مفتاح الحساب عبر `Authorization: Bearer`، ولا تضعه في رابط.

تنشئ قاعدة فاشلة سببًا آمنًا مثل Assertion 1: mismatch، وتفتح الحادث المقاس بعد عتبة الفشل الحالية وتستخدم الإشعارات وكتم الصيانة. لا تنشر إعلانًا عامًا أو تغيّر تعريف التوافر. تلف البيانات المشفّرة يتطلب إعادة إدخال بالمفتاح المهيأ. لا تستبدل المفتاح أو تدوّره دون حفظ الأسرار الحالية.

## استكشاف المشكلات

تحقق أولًا من المراقب والفترة والإعدادات المحفوظة. غياب الملاحظات لا يعني سلامة الخدمة. بعد الخطأ، احتفظ بالمسودة وصحّح الحقل أو المتطلب المشار إليه ثم أعد المحاولة عمدًا. إذا انتهت صلاحية المعاينة، أنشئ معاينة جديدة وراجعها قبل التطبيق.

## عناوين المراقبات

تقبل نماذج إنشاء مراقب والإضافة السريعة والإضافة الجماعية اسم مضيف مثل `example.com` وتعرض العنوان الموحّد `https://example.com/`. عند ترك الاسم فارغًا يُستخدم اسم المضيف. تقارن آلية كشف التكرار العناوين الموحّدة بمراقباتك الحالية وبالمجموعة الجديدة، بما في ذلك العناوين ذات الشرطة المائلة الأخيرة، وتعرض اسم المراقب الموجود. تبقى معلمات الاستعلام مؤثرة في المقارنة. تستخدم المراقبات الجديدة ثلاث حالات فشل متتالية افتراضيًا، ولا تتغير الحدود المحفوظة.

## الرموز المقبولة وTLS

يقبل حقل الحالة المتوقعة `200,204` و`2xx` و`200–299` ومجموعات منها. يجب أن تقع الرموز بين 100 و599 وأن تكون النطاقات تصاعدية. تستخدم الفحوص العادية والمتقدمة القاعدة نفسها. يحافظ الرمز المفرد على السلوك السابق. يؤدي إيقاف مفتاح مراقبة شهادة TLS في الإعدادات إلى إيقاف فحوص الانتهاء وتنبيهاتها ومسح نتيجة الشهادة المحفوظة. يبقى التحقق من نقل HTTPS مفعّلًا. تحتفظ القوالب وتصديرات الإعدادات بهذه الخيارات.

تحتفظ الإعدادات المشتركة أيضًا بقواعد رموز الحالة المقبولة وإعداد مراقبة TLS، دون نتائج الشهادات أو بيانات الاعتماد. عند نسخ مشاركة، تُقارَن العناوين القياسية بمراقباتك الحالية وبالدفعة المحددة، بما في ذلك مشاركاتك الخاصة.

## الأسماء والحفظ

الاسم اختياري عند إنشاء مراقب HTTP؛ إذا تركته فارغًا يُستخدم اسم المضيف من الرابط. تتطلب مراقبات DNS وTCP والخادم والنبض والقوالب المحفوظة اسمًا. يبقى الحفظ في نماذج التعديل معطّلًا حتى تختلف القيم عن النسخة المحفوظة. تؤدي إعادة القيم الأصلية إلى إزالة تحذير التغييرات غير المحفوظة. تظهر رسالة بجوار كل حقل غير صالح وملخص للأخطاء؛ عند الإرسال ينتقل التركيز إلى أول حقل غير صالح. فشل الحفظ يبقي المسودة.
