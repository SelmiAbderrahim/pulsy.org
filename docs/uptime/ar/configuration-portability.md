# الاستيراد والتصدير

افتح [الاستيراد والتصدير](/dashboard/import-export) لتصدير إعدادات المراقبين المحددين أو مراجعة إعدادات قبل استيرادها.

## الخطوات

افتح **التطوير → الاستيراد والتصدير** من قائمة التطبيق. حدّد مراقبين صراحة ثم صدّر الإعدادات المحدّدة. لا يتاح تنزيل JSON إلا بعد التصدير أو معاينة منقّحة ناجحة. تحميل ملف أو تعديل النص يلغي المعاينة والسماح بالتنزيل. الحدود 200 عنصر و256 KiB من JSON بصيغة UTF-8 وعمق 16 و20000 قيمة. تُنقل الإعدادات لا تاريخ الفحوص أو الحوادث أو النشر أو المشتركين أو المستلمين أو مفاتيح API أو النسخة الاحتياطية للتعافي. تتوفر الواجهة لكل حساب.

## تنسيق الملف

يحتوي الإصدار 1 على `format: "pulsy-monitor-configuration"` و`version: 1` ومصفوفة `monitors`. لكل عنصر `key` ثابت محلي للحساب و`type` و`name` و`interval` بالثواني و`active` و`tags`. المفاتيح بحروف وأرقام ASCII والشرطة السفلية والنقطة والنقطتين والشرطة، تبدأ بحرف أو رقم ولا تتجاوز 100 حرف. تبقى حساسية حالة الوسوم وحدود كل نوع. يتطلب HTTP أيضًا `url` و`method` و`expectedStatus` و`timeout` بالمللي ثانية و`failureThreshold` و`redirectPolicy`. القواعد `httpAssertions` والسياسة `latencyPolicy` اختياريتان: الإغفال يحفظ القيم الحالية وnull يعطّل سياسة الزمن. النبض يتطلب `graceSeconds`. يدعم الإصدار HTTP وDNS وTCP والنبض بفاصل. لا يدعم جداول cron أو محوّلات طرف ثالث.

## مثال

```json
{
  "format": "pulsy-monitor-configuration",
  "version": 1,
  "monitors": [{
    "key": "api-production", "type": "http", "name": "واجهة الإنتاج",
    "url": "https://example.invalid/health", "method": "GET",
    "expectedStatus": 200, "timeout": 10000, "interval": 300,
    "failureThreshold": 3, "redirectPolicy": "follow", "active": false,
    "tags": ["production"],
    "httpAssertions": [{ "type": "json", "path": "$.status", "op": "equals", "value": "ok" }]
  }]
}
```

## المفاتيح وإعادة التسمية

يستخدم التصدير المفتاح الخارجي الحالي أو `pulsy:<monitorId>` للمراقب غير المرتبط. تطبيقه في الحساب نفسه يربط المفتاح دون استبدال المراقب. ينشئ المفتاح الجديد مراقبًا جديدًا. لإعادة تسمية صريحة أضف `previousKey` بالمفتاح القديم المملوك واختر key الجديد؛ تُظهر المعاينة تغيير الارتباط. لا يحدد ذلك مراقبًا لحساب آخر. تُرفض المفاتيح القديمة المفقودة والعناصر التي تحدد المراقب نفسه مرتين وتعارض المفاتيح وتغيير نوع مراقب مرتبط. تكرار إعادة تسمية مطبّقة لا يكرر البيانات. احذف previousKey قبل نقل الملف إلى حساب آخر. المفاتيح حساسة لحالة الأحرف. لا تضع بيانات دخول في الأسماء أو الوسوم أو المفاتيح أو القواعد.

## القيم الخاصة والحدود

تُغفل قيم الطلب الخاصة ولا تُعاد أبدًا. يسرد `needsReentry` الفئات غير المملوءة: request أو url أو assertions أو heartbeatToken. تُغفل جميع الروابط ذات استعلام أو جزء تجزئة احتياطًا، وكذلك الروابط ببيانات دخول أو أسرار معروفة. url بقيمة null يحفظ رابطًا موجودًا؛ يحتاج مراقب جديد رابطًا آمنًا. تُغفل قواعد الترويسات الحساسة والقواعد المتضمنة قيم طلب معروفة. تبقى القواعد الحالية المغفلة. تُحذف حقول الطلب والمصادقة والمحتوى والرموز والمستلمين والمشتركين المستوردة قبل التحقق، وتُحذف تكرارات قيمها المعروفة في الأسماء والوسوم والروابط والقواعد. تستبدل المعاينة المحرر بنص JSON منقّح. تُرفض مفاتيح الكائنات الخطرة والحقول المجهولة والمفاتيح المكررة والإصدارات غير المدعومة. يُفحص حتى 500 قيمة خاصة مفردة لكل مراقب. هذه صيغة لحقول تحتاج إدخالًا وليست تكاملًا مع مخزن أسرار.

لا يستبدل الاستيراد أسرار الطلب المخزّنة ولا يمسحها. محتوى POST المحتفظ به يمنع التحول إلى GET/HEAD؛ امسحه أو استبدله عمدًا في الإعدادات أولًا. تبقى مراقبة HTTP الجديدة غير نشطة إن احتاجت قيمًا أو قواعد. لا يضم النبض رمزًا أو رابطًا: تبقى الوظائف الجديدة غير نشطة حتى تدوير الرمز ونسخه وتفعيلها في الإعدادات. يُحفظ تفعيل النبض الموجود بغض النظر عن active في الملف؛ استخدم أدواته الحالية. يتغير الفاصل والسماح دون اختلاق إيصال أو تعافٍ أو صحة. تبقى بصمات الرموز وتاريخ التشغيل.

يشير `channelIds` الاختياري إلى قنوات تنبيه موجودة يملكها الحساب فقط، دون مستلمين أو بيانات مزود أو وجهات تسليم. الإغفال يحفظ الروابط؛ المصفوفة الفارغة تزيل المراجع صراحة دون حذف القنوات. في تثبيت آخر احذف المراجع أو استبدلها بمعرفات يملكها ذلك الحساب. المرجع المفقود أو الأجنبي أو المحذوف أو غير المؤهل يرفض الاستيراد. القوالب والعروض وجداول الصيانة والمزودون وعضوية الصفحات العامة خارج هذا البيان.

## المعاينة والتطبيق

التحقق والمعاينة لا يكتبان ولا يفحصان وجهة. تُعرض تغييرات الحقول الدقيقة وأعداد الإنشاء والتحديث وعدم التغيير والرفض. التطبيق صريح وذري: رفض أي عنصر أو فشل تخزين أو إعداد قديم يمنع الجميع. تتحقق المراجعة من الإعدادات وهوية المراجع لا تغير الصحة المعتاد. يُسلسَل الإنشاء المتزامن بقفل معاملة على صف المالك، كما في المراقبة العادية والنبض، دون حد لعدد المراقبين. تبقى المعرفات والفحوص والحوادث والعضوية العامة والأسرار المغفلة. لا حذف أو تنظيف ضمني أو استبدال صامت. يبدأ HTTP النشط طلباته المجدولة وقد يؤثر POST على الوجهة. إعادة المعاينة تعرض عدم التغيير دون مراقبين مكررين. لا يوجد ما يُطبّق إن كانت جميع العناصر دون تغيير.

## الوصول عبر الواجهة البرمجية

يمكن لكل حساب استخدام مفاتيح API بنطاق `read` للقراءة و`full` للكتابة. أرسل مفتاح الحساب عبر `Authorization: Bearer`، ولا تضعه في رابط. يستخدم التصدير والمعاينة صلاحية القراءة، ويتطلب التطبيق `full`. تتوفر الواجهة بخمس لغات. يستخدم طلبا POST الأولان أدناه صلاحية القراءة:

```sh
curl -X POST "$PULSY_URL/api/v1/configuration/export" \
  -H "Authorization: Bearer $PULSY_API_KEY" -H 'Content-Type: application/json' \
  --data '{"monitorIds":["owned-monitor-id"]}'
curl -X POST "$PULSY_URL/api/v1/configuration/preview" \
  -H "Authorization: Bearer $PULSY_API_KEY" -H 'Content-Type: application/json' \
  --data-binary @preview-request.json
curl -X POST "$PULSY_URL/api/v1/configuration/apply" \
  -H "Authorization: Bearer $PULSY_API_KEY" -H 'Content-Type: application/json' \
  --data-binary @apply-request.json
```

يحتوي preview-request.json على `{"text":"<JSON-escaped native manifest>"}`، ويحتوي apply-request.json النص نفسه مع revision المعادة مثل `{"text":"<same escaped JSON>","revision":"<64-character revision>"}`. استخدم ترميز JSON القياسي في CI ولا تدرج ملفًا غير مهروب في أوامر shell. راجع المعاينة قبل السماح بخطوة التطبيق. المراجعة القديمة تعيد HTTP 409، والمدخل المرفوض أو غير الصالح 422، وحد المحلل 413، وJSON المشوّه 400، والضغط غير المدعوم 415. النجاح يستخدم no-store. لا CLI أو حزمة أو عامل مزامنة أو تجاوز للصلاحيات جديد.

يبقى مراقب HTTP غير نشط عند تكرار الاستيراد ما دامت قيم الطلب الخاصة أو قواعد التحقق المطلوبة والمحذوفة غير مضبوطة. اضبطها في إعدادات المراقب قبل طلب التفعيل من خلال استيراد لاحق. تُحفظ القيم الخاصة المضبوطة سابقًا.

يتضمن الإصدار1 الآن عناصر DNS وTCP أيضًا: تكون `type` بقيمة `dns` أو `tcp`، وتحمل `configuration` اسم المضيف والسجلات المتوقعة بحسب النوع أو اسم المضيف والمنفذ، مع المهلة وعتبة الإخفاق. تستخدم الفواصل المهيأة، وتحفظ السجل عند تحديث مفتاح مملوك، دون ادعاء فحص TLS أو نشر.

## استكشاف المشكلات

تحقق أولًا من المراقب والفترة والإعدادات المحفوظة. غياب الملاحظات لا يعني سلامة الخدمة. بعد الخطأ، احتفظ بالمسودة وصحّح الحقل أو المتطلب المشار إليه ثم أعد المحاولة عمدًا. إذا انتهت صلاحية المعاينة، أنشئ معاينة جديدة وراجعها قبل التطبيق.

## اختيار التصدير

استخدم **اختيار كل المراقبات المؤهلة** لاختيار حتى 200 مراقبة HTTP أو DNS أو TCP أو نبض مهمة. يُعطّل تصدير خوادم لينكس مع توضيح حاجتها إلى بيانات اعتماد وكيل جديدة، ويرفض الخادم هذه الطلبات أيضًا. تبقى ملفات الخوادم السابقة قابلة للاستيراد وتُنشئ خوادم معلقة غير نشطة تحتاج إلى إعداد جديد. يوفر **تنزيل نموذج** مثال HTTP غير نشط مستقلًا عن المحرر؛ ولا يحفظ **تنزيل JSON** إلا ملفًا مُصدّرًا أو مُراجعًا ومنقحًا.
