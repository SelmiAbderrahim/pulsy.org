# مراقبة DNS وTCP

تتوفر مراقبة DNS وTCP لكل حساب إلى جانب HTTP وإشارات النبض. يتبع سجل الفحوص إعداد المشغّل `CHECK_LOG_RETENTION_DAYS`.

## الخطوات

افتح قائمة «إضافة مراقب» واختر «مراقب DNS / TCP»، وأدخل الاسم والمضيف والفاصل والمهلة وعدد الإخفاقات المتتالية قبل التعطل. الإنشاء إجراء صريح؛ يبدأ المراقب المفعّل الفحوص المجدولة. التعطيل يوقف الفحص ولا يجعل الخدمة سليمة. الصيانة وكتم التنبيهات يمنعان الإشعارات مع استمرار الفحوص والسجل المقاس. الإقرار والملاحظات والإعلانات العامة منفصلة عن الصحة.

## مثال

يدعم DNS سجلات A وAAAA وCNAME وMX وTXT عبر محلل النظام الذي يضبطه المشغّل. الأسماء ASCII أو punycode، حتى253 حرفًا؛ تبقى بادئة الشرطة السفلية مثل `_acme-challenge.example.invalid` كما هي. أدخل اسمًا لا رابطًا أو منفذًا. اختر وجود سجل أو مطابقة مجموعة متوقعة بالضبط. أدخل التوقعات كمصفوفة JSON:

- A: `["1.1.1.1"]`؛ AAAA: `["2001:4860:4860::8888"]`.
- CNAME: `["api.example.invalid"]`.
- MX: `[{"priority":10,"exchange":"mail.example.invalid"}]`.
- TXT: `["Case Sensitive", ""]`. كل نص سجل كامل، وتُوصل أجزاء السجل الواحد. النص الفارغ يختلف عن غياب الإجابة.

يُتجاهل ترتيب السجلات وتكرارها في المقارنة. تُوحّد صيغ العناوين؛ تُتجاهل حالة أحرف أسماء CNAME وMX والنقطة النهائية، بينما تبقى أولوية MX مهمة. محتوى TXT والمسافات وحالة الأحرف دقيقة. تفشل الإجابات المتغيرة أو المحذوفة ولا تُعتمد تلقائيًا كخط أساس جديد. تغيير نوع السجل لا يستبدل التوقعات المدخلة؛ صححها قبل الحفظ.

تُميّز أسباب الفشل بين الاسم غير الموجود والإجابة الفارغة والخطأ المؤقت والمهلة وعدم المطابقة والعنوان المحظور وتجاوز الحدود. الحد50 سجلًا، و4KiB لكل TXT، و64KiB للتوقعات أو الإجابات الموحّدة، ومهلة60000 مللي ثانية. يُلغى الاستعلام عند الموعد النهائي. محلل النظام بنية موثوقة يضبطها المشغّل؛ لا يختار العميل خوادم DNS عشوائية هنا. لا تُحفظ أجسام الإجابات كبيانات رصد.

## السلوك

ينشئ TCP اتصالًا أصليًا واحدًا إلى اسم مضيف ومنفذ1–65535. تشمل المهلة التحليل وإنشاء الاتصال حتى60000 مللي ثانية. الاتصال الناجح سليم؛ الرفض والمهلة وفشل التحليل والوجهة المحظورة إخفاقات تخضع لعتبة الإخفاقات. يُغلق المقبس بعد كل محاولة. المنفذ المفتوح لا يثبت المصادقة أو صحة التطبيق أو شهادة TLS. فحص TCP TLS غير مفعّل.

تشترك القوائم والتفاصيل والسجل والحوادث والقنوات في مسار الصحة. مدة DNS مدة الاستعلام؛ مدة TCP تشمل تحليل الاسم والاتصال. الوحدات مللي ثانية، وليست تحميل صفحة متصفح. تستخدم قواعد التأخير الاختيارية المدد نفسها وعتبات التعافي. تبقى البيانات المجهولة محايدة والسجل المقاس محفوظًا؛ لا يصنع الإقرار أو الإعلان تعافيًا وهميًا.

## القيم الخاصة والحدود

تحافظ الوسوم على حالة الأحرف وحدود العناصر. تنسخ النسخ والقوالب إعدادات الشبكة غير السرية فقط، ثم تتطلب إنشاءً صريحًا، دون معرفات أو سجل أو حوادث أو نشر أو مستلمين. تؤثر تعديلات القوالب في الإنشاءات المستقبلية. تتضمن بيانات الإعدادات الأصلية بالإصدار1 إعدادات DNS/TCP والتوقعات المحدودة وسياسة المدة ومراجع القنوات المملوكة. المعاينة بلا كتابة؛ التطبيق إضافي وذري وقابل للتكرار دون حذف أو نشر ضمني. تستخدم مفاتيح API النطاق `read` للقراءة و`full` للكتابة، ويتوفر النطاقان لكل حساب.

تُحفظ الشرطة السفلية في أسماء أهداف CNAME. مجموعة MX الفارغة المتوقعة هي `[{"priority":0,"exchange":"."}]`، ولا يجوز أن تحتوي على سجلات MX أخرى. وتعني أن النطاق لا يقبل البريد عمداً، ولا تثبت إمكانية الوصول إلى خدمة SMTP ([RFC 7505](https://www.rfc-editor.org/rfc/rfc7505.html)). يقارن النظام اسم الجذر الفارغ من المحلل الأصلي بهذه النقطة الصريحة. تفشل إجابة MX الفارغة المختلطة أو ذات الأولوية غير الصفرية.

## استكشاف المشكلات

تحقق أولًا من المراقب والفترة والإعدادات المحفوظة. غياب الملاحظات لا يعني سلامة الخدمة. بعد الخطأ، احتفظ بالمسودة وصحّح الحقل أو المتطلب المشار إليه ثم أعد المحاولة عمدًا. إذا انتهت صلاحية المعاينة، أنشئ معاينة جديدة وراجعها قبل التطبيق.
