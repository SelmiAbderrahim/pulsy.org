# مخرجات Prometheus

## الخطوات

يقرأ GET /api/v1/metrics الحالة المخزّنة لمراقبي الحساب المصادق عليه فقط.
أنشئ مفتاحًا عاديًا من [التطوير ← مفاتيح API](/dashboard/api-keys). يمكن لكل حساب جمع المقاييس
باستخدام مفتاح بنطاق `read` أو `full`. لا ينفّذ الجمع فحوصًا أو استعلامات DNS أو
اتصالات أو مهام خلفية.

إذا اخترت تاريخ انتهاء لمفتاح API، فيجب أن يكون بعد اليوم بتوقيت UTC. ينتهي المفتاح في 23:59:59.999 UTC من اليوم المختار. دون تاريخ، يبقى صالحًا حتى إلغائه.

## إعداد الجمع

مثال إعداد؛ استبدل النطاق بنطاق تثبيتك:

```yaml
scrape_configs:
  - job_name: pulsy
    scheme: https
    metrics_path: /api/v1/metrics
    static_configs:
      - targets: ['pulsy.example.com']
    authorization:
      type: Bearer
      credentials_file: /etc/prometheus/pulsy-api-key
    scrape_interval: 60s
```

## السلوك

احفظ المفتاح في الملف المحدد بصلاحيات وصول مناسبة، وليس في الروابط أو
المستودع أو لقطات الشاشة. لتدويره أنشئ مفتاحًا بديلًا وحدّث الملف ثم ألغِ
القديم. تبقى قواعد انتهاء الصلاحية والإلغاء الحالية سارية.

المقاييس السبعة من نوع gauge وتبدأ أسماؤها بـ pulsy_monitor_:

## أمثلة استعلامات

- status: القيمة -1 مجهولة، 0 متوقفة، 1 تعمل، 2 متدهورة. تبقى الحالة مجهولة
  عند غياب فحص صالح أو عندما تكون pending.
- fresh: القيمة 1 فقط إذا كان المراقب مفعّلًا والحالة معروفة وعمر آخر فحص
  بين صفر وضعف الفاصل مع المهلة، شاملًا الحدين. تحتاج نبضات القلب أيضًا إلى
  سجل موعد محفوظ؛ ولا يجوز أن يتجاوز تأخر الموعد التالي عشر ثوانٍ إن وُجد.
- active: القيمة 1 للتفعيل و0 للإيقاف المؤقت.
- last_check_timestamp_seconds: وقت آخر فحص بثواني Unix، أو NaN عند غيابه.
- duration_seconds: مدة طلب HTTP أو حل DNS أو اتصال TCP بالثواني. يبقى
  الصفر صفرًا؛ والقيم المفقودة ونبضات القلب تعطي NaN.
- open_incident: القيمة 1 عند وجود حادث مقاس مفتوح، و0 خلاف ذلك.
- tls_expiry_timestamp_seconds: آخر انتهاء لشهادة TLS رُصد لمراقب HTTP
  بثواني Unix؛ أو NaN عند غيابه أو عند استخدام نوع مراقب آخر.

تكون fresh=0 للرصد القديم أو المؤرخ في المستقبل أو المراقب المتوقف مؤقتًا،
دون إعادة كتابة الصحة المخزّنة. تبقى نبضة القلب المتوقفة متوقفة حتى دون موعد
تالٍ. لا يثبت اتصال TCP صحة التطبيق. مدة المهمة ليست زمن استجابة الشبكة،
وتصدير الشهادة لا ينفّذ فحص TLS جديدًا.

## القيم الخاصة والحدود

اختر الحالات المعروفة والحديثة صراحةً:

```promql
pulsy_monitor_status{job="pulsy"} >= 0
  and on (job, instance, monitor_id) pulsy_monitor_fresh{job="pulsy"} == 1
```

التسمية الوحيدة هي monitor_id؛ لا أسماء أو روابط أو وسوم أو عناوين أو أسرار
أو محتوى استجابة. يقرأ استعلام محدود المراقبين والحوادث المفتوحة، مع قراءة
مجمّعة لمواعيد نبضات القلب عند الحاجة، دون مسح السجل. الحد 1000 مراقب في
الاستجابة؛ وتجاوزه يعيد 422. تستطيع التثبيتات الأكبر اختيار 1–200 معرّف
مفصول بفواصل عبر monitorIds. لا تُنتج معرّفات الحسابات الأخرى أو المعرّفات
غير الموجودة أي سلسلة.

يبقى حد API الحالي: افتراضيًا 60 طلبًا في الدقيقة لكل مفتاح، و429 مع
Retry-After. المفتاح غير الصالح يعيد 401، ونقص الصلاحية 403، والطلب غير
الصالح 422. تستخدم الاستجابات private, no-store؛ لا تضعها خلف ذاكرة تخزين
عامة مشتركة. بعد إعادة التشغيل تُقرأ السجلات الدائمة مجددًا. لا تُقدَّم
خدمة Prometheus أو Grafana مستضافة ولا تُفرض رسوم جديدة.

## استكشاف المشكلات

تحقق أولًا من المراقب والفترة والإعدادات المحفوظة. غياب الملاحظات لا يعني سلامة الخدمة. بعد الخطأ، احتفظ بالمسودة وصحّح الحقل أو المتطلب المشار إليه ثم أعد المحاولة عمدًا. إذا انتهت صلاحية المعاينة، أنشئ معاينة جديدة وراجعها قبل التطبيق.
